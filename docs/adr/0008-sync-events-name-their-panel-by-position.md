# Sync events name their panel by position; new panels are found by re-scanning on select

Sync events between pages followed only the current panel: the remote subscribed to the current browser's coordinator and applied a peer's event to whichever panel was current there. Two pages each holding heart and colon side by side drifted apart: a pan in heart on one page moved colon on the other, or nothing, depending on which panel each page last touched.

So every sync event carries `panel`, the sender's 1-based left-to-right position, the same vocabulary commands use (ADR-0007) and what `list_panels` prints. The remote follows every panel in `hic.getAllBrowsers()`, and a receiver applies an event to its panel at that position. A position the receiver lacks is dropped, with one exception: a `mapLoad` for exactly one past the receiver's panel count opens that panel, as `load_map panel:"new"` does, and loads the map there; this is what makes a clone-then-load on one page appear on its peers. juicebox.js announces no panel's creation or closing, so the remote scans the panel list again on every `BrowserSelect` and after every command and catch-up it runs itself. Every known way a panel is created (`load_map panel:"new"`, juicebox-web's clone button, restoring a session) selects the new panel, so the host requirement is stated in the remote's README instead of adding an event to juicebox.js: a host that creates a panel must select it. An event without `panel` comes from a remote older than this and applies to the current panel; no protocol version is added, since the field is additive and the server relays sync events unchanged.

Rejected: the browser guid (not serialized in a session, so it differs on every page); the map URL (two panels can show one map, and an empty panel has none); numbering only panels with a map (it would disagree with `list_panels`); a `BrowserCreate` event in juicebox.js (a fork change for something every creation path already signals by selecting); mirroring `BrowserSelect` (the current panel is cosmetic once commands and sync events name their panel).

Consequences: an empty panel is not in a saved session, so a late joiner restoring `[heart, empty, colon]` gets `[heart, colon]`, and positions differ by one until the empty panel gets a map. juicebox.js already syncs same-assembly panels within a page and each fires its own `onLocusChange`, so one drag sends one `locusChange` per synced panel; applying them is idempotent and the guard still prevents echo. A panel a host creates without selecting it is not followed until the next select, command or catch-up.

## Amendment (2026-09-30, ticket 33): opening and closing a panel are sync events

The count+1 rule did not hold up: two empty panels with a map loaded into the second first were dropped on a peer, a closed panel shifted every later event one panel off, and a late joiner restoring `[heart, empty, colon]` got `[heart, colon]`. The juicebox.js fork now posts `BrowserAdd` on the global bus once a browser is in `getAllBrowsers()` (before `BrowserSelect`) and `BrowserDelete` while it still is; a restore and `reset()` post neither.

So there are two more sync events, `panelOpen {panel}` and `panelClose {panel}`, sent on `BrowserAdd` and `BrowserDelete` with the position the panel takes or leaves, guarded like every other event, so a command or a catch-up restore does not echo them. A receiver opens an empty panel for `panelOpen` only at one past its last panel (the same `newPanel` as `load_map panel:"new"`) and drops any other position; it closes its panel at `panelClose`'s position with `hic.deleteBrowser` (registry fallback as `close_panel`), never the last one, and drops an unknown position. `mapLoad` no longer opens a panel: it applies to the panel at its position or is dropped.

A late joiner gets the empty panels: a page's answer to `getSession` lists one entry per panel in `getAllBrowsers()`, an empty one as `{}`, which juicebox.js restores as an empty panel. The room's stored 24-hour session (`hic.compressedSession()`) still skips empty panels; that only matters when no page is left.

The host requirement stays: a host that creates a panel must select it. A restore posts no `BrowserAdd`, and a juicebox.js without the events is still followed through `BrowserSelect`; on such a build peers are not told of a panel opening or closing. The Consequences' "positions differ by one" for a late joiner no longer applies.
